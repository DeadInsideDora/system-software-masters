# Системное программное обеспечение — магистратура

## Лабораторная работа 1. Вариант 6 — MoarVM

Ветка `lab1` содержит компилятор процедурного учебного языка на C. Задача —
разобрать исходную программу, построить промежуточное представление, сформировать
бинарный байткод MoarVM и выполнить его на виртуальной машине.

По заданию формирование модели и её сериализация разделены на модули:
генератор получает графы потока управления, сведения о переменных, сигнатурах
и типах, а сериализатор записывает сформированный образ в выходной файл.
Корректность результата проверяется запуском тестовых программ на MoarVM.

Компилятор напрямую записывает файл `.moarvm`, NQP не используется.

```text
Исходники → Flex/Bison → AST → CFG и модель программы → байткод → MoarVM
```

Реализованы:

- функции, прототипы, вызовы вперёд, рекурсия и компиляция нескольких файлов;
- целочисленная арифметика, сравнения, логические операции и присваивания;
- `if` / `else`, `while`, `do` / `while`, `break`, `continue`, `return`;
- строки, конкатенация, сравнение, индексация и длина строки;
- одномерные массивы `int[]` и `string[]`, передача и возврат массивов по ссылке;
- переменные без явного типа с динамическими значениями;
- ввод и вывод: `read`, `read_int`, `read_str`, `write`, `print_int`;
- диагностика ошибок, текстовая модель программы, листинг команд и DOT-графы AST/CFG.

## Требования

- C-компилятор (GCC или Clang), Make, Flex и Bison;
- MoarVM **2026.08** — эту версию устанавливает скрипт проекта;
- Perl, curl, tar, shasum и доступ к интернету для установки MoarVM;
- Graphviz (`dot`) для преобразования графов в изображения — необязательно.

Команды ниже выполняются в POSIX-окружении (например, macOS или Linux)
из корня репозитория. Сборка и запуск примеров проверены на macOS с MoarVM 2026.08.

## Быстрый запуск

```sh
git clone --branch lab1 git@github.com:DeadInsideDora/system-software-masters.git
cd system-software-masters

make setup-vm
make
make demo
```

`make setup-vm` скачивает исходники MoarVM, проверяет SHA-256, собирает и
устанавливает VM в `.local/moarvm`. Права администратора не нужны.
Если подходящая VM уже установлена, этот шаг можно пропустить:
`tools/moar.sh` ищет её сначала по переменной `MOAR`, затем в `.local/moarvm/bin/moar`,
затем в `PATH`.

```sh
export MOAR=/absolute/path/to/moar
```

`make` создаёт компилятор `build/moarvmdirect`. `make demo` компилирует и запускает
примеры на MoarVM, сохраняет графы и листинги штатного дизассемблера.

## Компиляция своей программы

```sh
mkdir -p output/lab1
build/moarvmdirect output/lab1/strings.moarvm examples/lab1/strings.src
./tools/moar.sh output/lab1/strings.moarvm
```

Ожидаемый вывод программы:

```text
Hello, Alice!
Hello, Боб!
Hello, Cat!
1
6
```

Общий формат команды:

```text
build/moarvmdirect [--graphs directory] output.moarvm input1 [input2 ...]
```

В программе должна быть функция `main()` без аргументов. Несколько входных
файлов объединяются в одну программу. Родительский каталог выходного файла
нужно создать заранее.

## Примеры

| Команда / файл | Что демонстрирует |
| --- | --- |
| `make demo` | Запускает `strings`, `calls`, `arrays`, `control`, сохраняет графы и листинги в `output/lab1` |
| `examples/lab1/strings.src` | Строки, Unicode, массив строк; вывод приведён выше |
| `examples/lab1/calls.src` | Рекурсия, взаимная рекурсия, инициализация; результаты `720`, `1`, `7` |
| `examples/lab1/arrays.src` | Возврат массива и изменение через общую ссылку; результат `65` |
| `examples/lab1/control.src` | Циклы и короткое вычисление логических операций; результат `14 0` |
| `make calc` | Интерактивный калькулятор (`examples/lab1/calc.src`) |
| `make cats-dogs` | Отбор индексов по звуку и получение имён животных через массивы и функции |

Калькулятор принимает начальное число, затем операцию (`+`, `-`, `*`, `/`, `%`)
и следующий операнд. Записывайте ввод по одному значению на строку.
Операнд `!4` означает факториал 4, `f6` — шестое число Фибоначчи; `q` завершает работу.

```sh
printf '5\n+\n!4\n*\nf6\nq\n' | make calc
```

Результаты вычислений: `29`, затем `232`.

## Графы и листинги

```sh
mkdir -p output/lab1
build/moarvmdirect --graphs output/lab1/calls-graphs \
  output/lab1/calls.moarvm examples/lab1/calls.src
./tools/moar.sh --dump output/lab1/calls.moarvm

# Необязательно: изображение исходного AST, нужен Graphviz.
dot -Tpng output/lab1/calls-graphs/unit-0.ast.dot \
  -o output/lab1/calls-graphs/ast.png
```

Рядом с байткодом компилятор записывает `.moarvm.model.txt` (модель программы)
и `.moarvm.dump.txt` (собственный листинг). Флаг `--graphs` добавляет исходные
и преобразованные AST и графы потока управления функций в формате DOT.
`moar --dump` независимо читает полученный бинарный файл.

## Структура проекта

| Файлы / каталог | Назначение |
| --- | --- |
| `lexer.l`, `parser.y`, `parse_module.*` | Лексический и синтаксический анализ |

| `moarvm_direct.*`, `moarvm_ops.h` | Генерация команд MoarVM |
| `moarvm_image.*`, `moarvm_dump.c` | Бинарный образ, сериализация и листинг |
| `moarvm_direct_main.c` | Командный интерфейс компилятора |
| `examples/lab1/` | Основные примеры лабораторной |
| `tools/` | Установка и запуск MoarVM |

## Ограничения

Числовые типы и их псевдонимы представлены знаковым 64-битным целым.
Массивы одномерные; область видимости переменных — функция.
Классы, замыкания и FFI в этой лабораторной не реализованы.
У `read()` конец ввода и нулевой байт обозначаются одинаково — `0`.
Память объектов исполняемой программы обслуживает сборщик мусора MoarVM.
