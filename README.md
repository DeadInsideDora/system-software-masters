# Лабораторная работа 2 — вариант 4

Компилятор учебного языка на C с генерацией байткода MoarVM.
Вариант 4: **функциональный тип, локальные функции и замыкания**
(`first-order function type + local functions + closures`).
Целевая виртуальная машина — MoarVM (вариант 6 первой лабораторной).

Поддерживаются:

- типы функций `fn(типы аргументов) -> тип результата`;
- присваивание функций переменным, передача аргументами и возврат из функций;
- локальные функции, в том числе рекурсивные;
- замыкания с захватом переменных внешней функции и сохранением их состояния
  после её завершения.

## Требования

- GCC или Clang, Make, Flex, Bison;
- MoarVM 2026.08;
- для установки MoarVM скриптом: Perl, curl, tar, shasum и доступ к интернету.

Команды выполняются из корня проекта в macOS или Linux.

## Сборка и запуск

```sh
git clone --branch lab2 git@github.com:DeadInsideDora/system-software-masters.git
cd system-software-masters
make setup-vm
make
make demo-lab2
```

`make setup-vm` скачивает и собирает MoarVM в `.local/moarvm`.
Если VM уже установлена, вместо этого шага можно указать путь:

```sh
export MOAR=/absolute/path/to/moar
```

`make` создаёт компилятор `build/moarvmdirect`.
`make demo-lab2` компилирует и запускает пять примеров из `examples/lab2/`:

| Пример | Что показывает |
| --- | --- |
| `counter.src` | Независимые счётчики-замыкания; вывод `11 12 101 1` |
| `compose.src` | Композиция функций; вывод `22` и `21` |
| `shared_state.src` | Общее состояние двух замыканий; вывод `40 41 41` |
| `local_recursion.src` | Взаимная рекурсия локальных функций; вывод `1 0` |
| `lazy_animals.src` | Ленивые итераторы, фильтрация и преобразование через замыкания |

Отдельный запуск примера с животными:

```sh
make demo-lazy
```

Он выводит имена кошек и собак. Символ `@` отмечает каждый вызов продвижения
исходного итератора, показывая, когда запрашивается очередной элемент.

Интерактивная демонстрация счётчиков и передачи функций:

```sh
make demo-interactive
```

Введите номер команды из меню и нажмите Enter; `0` завершает программу.

## Компиляция отдельной программы

```sh
mkdir -p output/lab2
build/moarvmdirect output/lab2/counter.moarvm examples/lab2/counter.src
./tools/moar.sh output/lab2/counter.moarvm
```

Общий формат:

```text
build/moarvmdirect [--graphs directory] output.moarvm input1 [input2 ...]
```

В программе должна быть функция `main()` без аргументов. Каталог выходного
файла нужно создать заранее. Несколько исходных файлов можно передать одной
командой.

Рядом с байткодом создаются `.moarvm.model.txt` и `.moarvm.dump.txt`.
Параметр `--graphs` сохраняет AST и графы потока управления в формате DOT.
Для просмотра байткода средствами VM:

```sh
./tools/moar.sh --dump output/lab2/counter.moarvm
```

Результаты сборки и запуска находятся в `build/` и `output/` и исключены
из Git вместе с локальной установкой VM. `make clean` удаляет `build/`.
